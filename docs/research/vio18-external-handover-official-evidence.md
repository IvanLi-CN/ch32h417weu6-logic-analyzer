# CH32H417 External VIO18 Official Evidence

## Scope

This note uses only WCH's CH32H417 data sheet, reference manual, and official
SDK. It does not use a reference project, a board test, or inferred reset
behavior.

The published WCH reference manual is now included as the controlling source
for reset registers and VIO18 encodings. See [the complete official
analysis](ch32h417-external-vio18-dac-control-official-analysis.md).

This note concerns only the independent external-rail source and handover. It
does not make `VIO18` the HSADC reference voltage; the separate HSADC
steady-state supply conditions are defined in
[CH32H417WEU6 HSADC and VIO18 Operating Constraints](ch32h417weu6-hsadc-vio18-constraints.md).

## Evidence

| Question | Official evidence | Conclusion |
| --- | --- | --- |
| What normally drives `VIO18`? | CH32H417 data sheet, Section 1.4.3, page 8: `VIO18` is normally generated by the I/O-pin LDO powered from `VDDIO`. | The normal source is the internal LDO. |
| Can the internal LDO be changed or disabled? | WCH-RM v1.7, Section 2.4.1, `PWR_CTLR.VSEL_VIO18[2:0]`, maps every encoding and defines `111b` as LDO off with output floating. It gives an exposed-`VIO18`, fixed-3.3-V `VDDIO`--`VIO18` short as the documented external case. | Software control and the off encoding are proved. WCH does not extend that proof to the project's independent external rail. |
| What does the `XO` resistor do? | Data sheet Table 3-2: a pull-down on `XO` selects the **internal LDO's** power-up default. 220-400 kOhm selects 2.5 V; 60-110 kOhm selects 1.2 V; 1.2 Mohm through floating selects 1.8 V. | This table does not describe or approve an external-regulator handover. It is not sufficient evidence to add `300 kOhm` for that purpose. |
| Does WCH endorse software VIO adjustment with attached external devices? | Official SDK example [`PWR/SEL_VIO18`](https://github.com/openwch/ch32h417/blob/main/EVT/EXAM/PWR/SEL_VIO18/V3F/User/main.c) states that hardware configuration is recommended to ensure external-device safety. | The official example points away from using an assumed software transition as a safety mechanism for an externally connected circuit. |
| Is `PA5` reset high impedance? | WCH-RM v1.7, Sections 9.2.2 and 9.3.1.1: `R32_GPIOA_CFGLR=0x44444444`; PA5 therefore has `CNF5=01b` and `MODE5=00b`, which is floating input. | Yes. PA5 is a GPIO floating input at reset. This does not establish a passive 2.5-V feedback state or an independent external-VIO18 handover. |
| Can DAC data be written before enabling the channel? | WCH-RM Chapter 18 gives independent DAC2 holding-register and `EN2` control; Table 18-2 resets the holding registers and `DOR2` to zero, and `DAC_CTLR.EN2=0` disables channel 2. The SDK has separate `DAC_SetChannel2Data()` and `DAC_Cmd()` functions. | Firmware can write the holding register before `DAC_Cmd()`; reset leaves DAC2 disabled. This does not establish an independent external-VIO handover guarantee. |

## Design Conclusion

The following proposal is unsupported and shall not be used as an instruction to
modify the schematic:

- add `300 kOhm` from `XO` to GND to coordinate with an external regulator;
- replace the existing EA3036C CH2 feedback network with a DAC injection
  network;
- treat the PA5/DAC2 reset state as sufficient proof of a passive 2.5-V
  feedback state;
- join an external CH2 output and the internal `VIO18` LDO on the assumption
  that equal nominal voltages make the connection safe.

The product requirement for external `VIO18` remains valid. However, the
published WCH material still requires an official application circuit or
electrical specification for independent external `VIO18` before changing
the existing external-VIO18 schematic or defining its internal-LDO interaction.
This is a documentation boundary, not a request for board testing or a
placeholder component.
