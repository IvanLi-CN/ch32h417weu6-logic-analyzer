# CH32H417 External VIO18 DAC-Control Official Analysis

## Decision

The project requirement is an independently supplied, DAC-adjustable external
VIO18 rail: EA3036C CH2 supplies the MCU, capture buffer, and I2C pull-ups;
it is never tied to VDDIO and has 1.80 V, 2.50 V, and 3.00 V modes. Those are
existing project facts from [Power Architecture](power-architecture.md), not
evidence imported from another project.

Official WCH material proves the MCU reset state and the internal I/O-LDO
control encoding. It also documents one different external connection: a fixed
VIO18 = VDDIO connection when low-voltage operation is not needed. It does not
establish the project's independently regulated rail, its power-transition
behavior, or a safe external-LDO handover. Therefore the external-VIO18
DAC-control topology cannot be claimed safe from official evidence.

**no schematic change is justified from official evidence.**

## HSADC Steady-State Boundary

This analysis addresses the independent external-`VIO18` rail's source, reset,
and internal-LDO handover only. It does not determine the HSADC conversion
supply constraints. Those steady-state values are defined in
[CH32H417WEU6 HSADC and VIO18 Operating Constraints](ch32h417weu6-hsadc-vio18-constraints.md):
`VDD33A = VREFP(internal) = VDDIO = 3.32 V`, while `VIO18` remains selected at
1.80 V, 2.50 V, or 3.00 V.

Meeting those HSADC steady-state inequalities does not close the independent
external-rail startup or handover evidence gap documented below.

## Fact Matrix

| Required fact | Official evidence | Finding |
| --- | --- | --- |
| Is external VIO18 allowed? | WCH-DS Section 1.4.3 says VIO18 is normally generated by the VDDIO-powered I/O LDO, permits 1.2/1.8/2.5/3.3 V or off, and states it can be fixed shorted to VDDIO when low voltage is unnecessary. WCH-RM PWR_CTLR.VIO_SW_CR note defines the exposed-VIO18, 3.3-V case as an external VDDIO--VIO18 short. | Yes, but only for the documented fixed same-rail connection. It is not a specification for a separately regulated 1.80/2.50/3.00-V rail. |
| May the I/O LDO be disabled while externally driven? | WCH-RM PWR_CTLR.VSEL_VIO18[2:0] encodes 111b as LDO off with output floating. Its exposed-VIO18, 3.3-V note directs software to set VSEL_VIO18=111b after power-up. | Yes for the documented VDDIO = VIO18 = 3.3 V short. No WCH source authorizes that action for the project rail, which is independent of VDDIO. |
| What is the exact PWR reset state and level mapping? | WCH-RM Section 2.4.1: R32_PWR_CTLR resets to 0x00000000; VIO_SW_CR bit 9 resets to 0 and selects the XO pull-down hardware default. VSEL_VIO18[2:0] bits 12:10 reset to 000b: 000=1.2 V, 001=1.8 V, 010=2.5 V, 011=3.3 V, 100=off with 10 mA discharge, and 101/110/111=off with output floating. | The levels and reset state are proved. Before firmware changes bit 9, the XO-selected internal-LDO state applies. |
| What does XO prove? | WCH-DS Table 3-2 maps an XO pull-down of 220-400 kOhm to a 2.5-V internal default; 1.2 Mohm through floating to 1.8 V; and 60-110 kOhm to 1.2 V. WCH-RM names 330 kOhm, floating, and 100 kOhm as the nominal choices. | A 300-kOhm XO pull-down establishes only the internal 2.5-V default. It does not create a passive external-rail handover or a PA5 feedback voltage. |
| What is PA5 electrically at reset? | WCH-RM register list: R32_GPIOA_CFGLR=0x44444444 at reset. In Section 9.3.1.1, each CNFy reset value is 01b and each MODEy reset value is 00b; for y=5 this is floating input. | PA5 is a GPIO floating input at reset. The earlier assumption that this was unproved is corrected. |
| What is DAC2 at reset and how is it controlled? | WCH-RM Table 18-2: R32_DAC_CTLR=0x00000000, every DAC2 holding register, and R32_DAC_DOR2 reset to zero. Section 18.4.1: EN2=0 disables DAC channel 2; BOFF2=0 opens the output buffer; TEN2=0 gives the non-trigger transfer. Sections 18.2.2 and 18.2.3 require configuring the pin as AIN before enabling DAC, write a DAC2 holding register to update DOR2 after one HB clock in non-trigger mode, and state that output becomes valid after a supply/load-dependent settling time. | Reset leaves the PA5 GPIO path floating and DAC2 disabled. Data/enable behavior is defined, but no numeric DAC settling time or regulator-rail sequence is supplied for this topology. |
| Is the EA3036C CH2 feedback topology tied to PA5 safe at reset? | The WCH-side reset state is known: PA5 floats and EN2=0. The project topology, however, has an independently regulated external VIO18 that is never tied to VDDIO. | It cannot be claimed safe from WCH evidence. A high-impedance MCU pin is not evidence that WCH permits the independent supply connected to VIO18 during reset or LDO state transitions. |
| What power-up or power-down sequence is required? | WCH specifies the initial XO-controlled LDO state, software modes, and the fixed 3.3-V short case. WCH-EVT's SEL_VIO18 example changes to software mode and MODE3 (3.3 V), while warning that hardware configuration is recommended for external-device safety. | No official WCH power-up, power-down, ramp, back-drive, or handover sequence exists for the independent project rail. None can be manufactured from the documented register writes. |

## Strict-Constraint Comparison

Only options that retain an external rail, add no IC, and avoid DNP/reserved
workarounds were considered.

| Candidate | Meets project network facts? | WCH support | Result |
| --- | --- | --- | --- |
| Existing independent EA3036C CH2 rail with PA5/DAC2 feedback | Yes: external, DAC-adjustable, 1.80/2.50/3.00 V, and not tied to VDDIO. | No published WCH specification covers independent external VIO18 drive or its internal-LDO handover. | Cannot be claimed safe. |
| XO 300-kOhm default plus a passive 2.5-V handover | Structurally retains an external rail, but does not add a defined control path. | Table 3-2 only proves an internal-LDO 2.5-V default. | Rejected. It is not a documented external supply or feedback mechanism. |

The WCH fixed VDDIO--VIO18 short is not included as a candidate because it
contradicts the existing project rail: it eliminates the required independent,
selectable external VIO18 domain.

## One Blocking Evidence Gap

The single blocking WCH evidence gap is an official electrical specification or
application circuit for an **independent external VIO18 supply that is not
tied to VDDIO**, including its allowed overlap with the internal I/O LDO and
the required power-up/power-down transition conditions. The data sheet and
reference manual provide only the internal-LDO configuration and the fixed
same-rail short case.

Without that source, neither a schematic modification nor a firmware handover
sequence is supportable. This conclusion does not request board testing and
does not substitute an optional, DNP, or reserved circuit for the missing
evidence.
