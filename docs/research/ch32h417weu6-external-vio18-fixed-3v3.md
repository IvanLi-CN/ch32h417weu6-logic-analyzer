# CH32H417 WCH Documented Fixed 3.3 V VIO18 Topology

## Scope

This note records the one externally bonded `VIO18` topology directly
described by WCH: a fixed 3.3-V `VDDIO`--`VIO18` short with software shutdown
of the internal I/O LDO after power-up. It is not the project topology.

The project requires independently regulated `VIO18` modes of 1.80 V, 2.50 V,
and 3.00 V. Its HSADC steady-state constraints are documented in
[CH32H417WEU6 HSADC and VIO18 Operating Constraints](ch32h417weu6-hsadc-vio18-constraints.md).
The separate startup and handover guarantee for that independent rail remains
outside the published WCH evidence.

## WCH Reference Implementation

Use one externally generated 3.3-V rail for both supply domains:

```text
external 3.3-V regulator output
    |
    +-- CH32H417WEU6 VDDIO pins
    |
    +-- CH32H417WEU6 VIO18 pins
```

- Directly short all `VDDIO` and `VIO18` pins on the PCB. This is a fixed
  connection, not a regulator handover and not two separately regulated rails.
- Keep the rail within both supply ranges and preserve the data-sheet relation
  `VDDIO >= VIO18`; the direct short makes that relationship true by
  construction.
- Fit the data-sheet local decoupling for each supply pin: `0.1 uF` at every
  `VDDIO` and `VIO18` pin, plus at least `10 uF` at the main `VDDIO` pin and
  `2.2 uF` at the main `VIO18` pin.
- Do not add a 100-kOhm or 330-kOhm pull-down at `XO` to select an I/O-LDO
  voltage. Preserve the oscillator network required by the clock design.
- Do not connect `PA5` to a regulator feedback, enable, or voltage-select
  node. No DNP option, series isolation part, or reset-time analogue workaround
  is required because the pin has no role in this topology.

The data sheet explicitly states that `VIO18` is normally generated by the
I/O-pin LDO, but that it can be fixed shorted to `VDDIO` when low-voltage
operation is not required. The reference manual gives the matching
externally-bonded-`VIO18`, 3.3-V procedure and explicitly requires the same
short plus software LDO shutdown after power-up. Those are direct WCH
instructions, rather than an inference from two equal nominal voltages.

## Startup Software

For the WCH fixed-short topology, run the following ordered PWR operation at
the first startup point where the PWR register is writable, after the board's
3.3-V rail has powered up and before configuring capture I/O or enabling any
capture buffer.

```c
/* R32_PWR_CTLR: VSEL_VIO18 is bits [12:10]; VIO_SW_CR is bit 9. */
uint32_t ctlr = PWR->CTLR;

/* Keep reset's hardware-selection mode while preparing the off setting. */
ctlr &= ~((0x7u << 10) | (1u << 9));
ctlr |=  (0x7u << 10);               /* VSEL_VIO18 = 111b */
PWR->CTLR = ctlr;

/* Select software control: internal VIO18 LDO is off and output floats. */
PWR->CTLR = ctlr | (1u << 9);        /* VIO_SW_CR = 1 */
```

`VSEL_VIO18=111b` means the internal `VIO18` LDO is off with a floating
output. Do not use `100b`: WCH specifies that value as LDO-off with a 10-mA
discharge, which would intentionally load the externally tied 3.3-V rail.
The first write is ordered before `VIO_SW_CR=1` so the reset default does not
briefly select software-controlled 1.2 V.

There is no runtime `VIO18` transition in this WCH topology. The hardware rail
remains at 3.3 V through POR, reset, firmware startup, and normal operation;
the software step only removes internal-LDO consumption after power-up.

## DAC2 and PA5 During Reset

The question is resolved by removing `DAC2` and `PA5` from the supply-control
path, not by trying to qualify a DAC-controlled regulator at reset.

| Statement | Official evidence | Design consequence |
| --- | --- | --- |
| The PWR reset value is deterministic. | `R32_PWR_CTLR` resets to `0x00000000`; `VIO_SW_CR=0` selects `XO` hardware configuration. | Before firmware runs, the documented fixed `VDDIO`-to-`VIO18` short is the complete supply topology. |
| DAC2 starts disabled. | `R32_DAC_CTLR` resets to `0x00000000`; `EN2` resets to `0` and `0` means channel 2 disabled. DAC2 data registers also reset to zero. | There is a register-level reset guarantee that DAC2 is disabled. It is not used by the VIO18 implementation. |
| PA5 is DAC2's default output pin. | The data sheet maps `DAC2_OUT` to `PA5`. The GPIO chapter states that most I/O pins reset as floating inputs, but does not give a PA5-specific analogue output-impedance specification. | Do not treat the general GPIO reset description or `DAC_EN2=0` as a guarantee that PA5 is safe as a regulator feedback node. PA5 is disconnected from the rail-control circuit, so that missing guarantee is irrelevant. |
| The official 3.3-V VIO18 method does not name DAC2 or PA5. | The PWR procedure names only `VDDIO`, `VIO18`, `VSEL_VIO18`, and the internal LDO. | DAC2 and PA5 cannot influence VIO18 selection during reset or normal operation in the implemented topology. |

## Boundary

This WCH reference topology is valid only for fixed 3.3-V operation with
`VDDIO` and `VIO18` shorted. It does not establish a safe external 1.8-V,
2.5-V, or adjustable-VIO18 rail, nor a firmware handover between an external
regulator and the internal I/O LDO. Such a design needs a separate WCH primary
source that explicitly covers that topology; it must not be inferred from the
software voltage-selection register or from DAC2 reset values.
