## 原始工程设计

### 数字采样与 USB

- 主控：`CH32H417QEU6`，原工程 BOM 使用 QFN-128 封装。
- 通过 CH32H417 的 UHSIF 高速接口采集最多 16 路数字信号，项目页标称 200MHz 连续采样。
- USB-C 支持 USB 3.0 5Gbps，也兼容 USB 2.0。
- USB 3.0 模式下，项目页将 16 通道 200MHz 作为目标能力；USB 2.0 模式受带宽限制，8 通道为 40MHz、16 通道为 20MHz。
- 可采逻辑电平范围为 1.2V-5V，触发阈值页面标注 0.8V-2.3V，I/O 耐压标注 0V-5.8V。项目页同时明确说明输入暂未做高压防护。
- 理论连续采样时间取决于 PC 内存；页面给出的例子是 64GB 主机在 16 通道下可采约 16 秒。

### 模拟采样

- 使用 CH32H417 HSADC，项目页标注 2 通道、最高 20Msps、0V-4.5V。
- 由于 DMA 不能自动动态切换，两个模拟通道不能同时采样，任意时刻只能采 1 路。
- 数字采样和模拟采样可以同时使用，但需要在 PC 上打开两个软件实例。
- 模拟前端使用 OPA2322，通过分压和跟随器把输入范围扩展到接近 5V。

### 电源、Type-C 和指示

- `CH2003K` 从 Type-C VBUS 获取 5V，内部 LDO 产生 3.3V，同时在 MCU DAC 控制下产生约 1.2V-3.3V 的可调 VIO18 电源。
- VIO18 用于 UHSIF I/O 独立供电，使逻辑电平和触发阈值可调；项目页说明高于 3.3V 的外部信号使用 3.3V 触发阈值。
- `CH9441P` 负责 Type-C 正反插自适应和 USB 3.0 路径切换。
- 当前短路保护使用 PTC；项目页记录下一版考虑使用低压降的 `CH213`。
- 三个 LED 分别表示上电、固件运行、USB 连接/传输状态。

### PC 软件与固件

工程包含 IAP 和 APP 两个 MCU 工程，页面给出的流程是：

1. 使用 MRS2 编译 IAP 的 V3F 固件。
2. 通过 WCH-LinkE 和 SWD 下载 IAP。
3. 编译 APP 的 V3F、V5F 固件。
4. 安装分卷压缩的 Windows 版 `U3LogicAnalyzer`，再用软件内置的固件升级功能下载 APP。

页面还说明 USB/串口 ISP 引脚当前没有直接引出；如需使用 ISP，需要自行在 PCB 上拉线。IAP 工程、APP 工程和 PC 软件源码均有附件或压缩包入口。

## 评论采集结果

评论区默认按时间排序，共 12 页。抽取结果包含 117 条主楼和 375 条回复，共 492 条；主楼楼层从 117 楼到 1 楼。作者账号 `elctr0` 共出现 157 条，是评论区主要维护者。评论原文和楼层关系以[项目评论区](https://oshwhub.com/q2h2/project_bszkxrnf#5)为准。

### 高频主题

1. **复刻与硬件排障**：用户集中反馈 USB 不识别、Type-C 焊接、功耗/温升、晶振、供电和转接板兼容问题。评论中最重要的已确认事项是：旧版 1.27 转 2.54 转接板可能造成 VIO18 短路，作者已置顶说明新版配件已修复，旧版不再使用。
2. **固件和 PC 软件**：讨论集中在 IAP/APP 双固件流程、MRS2 编译、WCH-LinkE、USB 2.0 回退、`U3LogicAnalyzer` 解码器目录和打包安装。有人遇到协议解码器缺失，最终通过卸载后换安装路径重装恢复。
3. **模拟 ADC**：用户反馈 5V@1kHz 输入读数只有约 700mV、ADC 量程不合适、10bit 采样不完整和希望增加 ADC 通道。作者解释前端分压可能压低读数，并表示后续上位机将支持 ADC 量程调节；另有衍生工程声称修复了 10bit 采样不完整问题。
4. **采样精度与时间轴**：101 楼用户报告以外部 FPGA 产生测试信号时，疑似每 8192 个周期丢一个时间片；作者要求确认测试链路和“UHSIF 输出 CLK”的具体含义。项目描述另记录 `pre0v5` 已修复某类单次采样 bit 丢失问题，两者不能直接视为同一个问题已经解决。
5. **机械和配件**：1.27mm 排针、2.54mm 改版、转接板、外壳孔位和亚克力面板是高频讨论点。孔位是否匹配取决于排座/转接板的具体规格，不能只按“1.27mm”这个间距判断。
6. **扩展请求**：有用户建议增加 FRAM 或 LPDDR 做 buffer 模式；最近的 116 楼 LPDDR、115 楼 4.7uF/10uF、113 楼 15pF/1K 电阻选型问题，在采集页面中尚未看到作者答复。

### 复刻经验中的关键边界

- 作者认为整板约 110mA 功耗可以正常，但“明显发烫”不应直接视为正常；一个缩小版衍生工程报告主控约 60℃，作者解释小 PCB 的热密度会更高。
- 有用户报告某 USB 口测得 5V 线路只有 3.7V-3.9V；作者判断这不正常，建议排查短路或测量方式，并指出 LED 限流电阻偏小会增加约 110mA 总功耗。
- 触发阈值必须和实际信号电平匹配。作者特别指出，1.5V 信号处于某些 I/O 高低电平判定的不确定区间时，即使偶尔被识别为高电平，也不应作为可靠配置。
- IAP 正常运行时，作者建议通过 TX1 观察 921600 波特率串口输出；USB 不识别时优先检查 Type-C 焊接、USB 线、USB 3.0 Hub 和 IAP/APP 下载流程。
- 作者明确表示目前没有制作整板成品的计划，想购买已贴片 PCBA 的用户只能等待社区自发组团或自行复刻。

## QEU6 原工程迁移到 WEU6 的注意事项

### 页面和作者明确的信息

原项目 BOM 使用的是 `CH32H417QEU6`，不是 `CH32H417WEU6`。评论 55 楼附近，作者回复称 WEU6 手册中“不完整”主要涉及没有引出的部分引脚，但该逻辑分析仪使用的 16 个 I/O 都有，社区已有 WEU6 复刻成功案例；同时提醒必须注意 QEU6 与 WEU6 的供电和电源系统差异。

作者还解释过，QEU6 将 UHSIF 与 HSADC 分属不同电源域，模拟采样范围不随逻辑触发电平改变；更小封装的替代方案可能让 UHSIF/HSADC 共用 VIO18，从而使 ADC 量程和逻辑触发电平耦合。这个解释属于作者在评论中的工程判断，不能替代对应封装的数据手册核对。

对本项目的 WEU6，规范性稳态结论以 WCH 数据手册和参考手册为准：
`VDD33A = VREFP（封装内） = VDDIO = 3.32 V`，`VIO18` 仍可选择 1.80 V、
2.50 V 或 3.00 V，且不得高于 `VDDIO`。HSADC 量程由 `VREFP/VDDIO` 决定，
约为 `0 V` 至 `3.32 V`，不随 `VIO18` 档位变化。详见
[WEU6 HSADC 与 VIO18 稳态约束](ch32h417weu6-hsadc-vio18-constraints.md)。这只澄清
HSADC 的稳态电压条件；独立外部 `VIO18` 的上电和 LDO 交接仍缺少 WCH 官方保证。

### 社区讨论中的待验证事项

评论区用户进一步提出了以下 WEU6 风险：

- WEU6 未引出 QEU6 使用的部分 ADC/VREF 引脚，模拟采样需要改用其他引脚并修改固件。
- WEU6 的 logic/analog 电源域耦合更紧，若继续使用 HSADC，I/O 电平和 ADC 供电条件需要重新核对。
- WEU6 的 UHSIF 端口位宽或缓冲区相关引脚可能不完整；有用户推断可使用 `UHSIF_PORT_RM=01`，但这属于社区依据手册的讨论，不是本项目页面的最终验证结论。
- 社区有一个移植到 WEU6 的 Mini 版本讨论，也有用户报告逻辑采集功能成功，但 ADC 未充分验证；这些结果不能直接证明本仓库的 WEU6 硬件和引脚映射正确。

因此，对当前 WEU6 方向最稳妥的复用边界是：保留原工程的 UHSIF/USB 3.0 设计思路作为参考，重新核对封装引脚、电源域、VREF/ADC 通道、ISP/串口可用性和 UHSIF 端口配置；不要直接复制 QEU6 的 ADC 引脚和 VIO18 控制代码。

## 结论

这个项目的核心价值是用 CH32H417 的 UHSIF 和 USB 3.0 实现单芯片、16 通道、200MHz 连续逻辑采样，并把 PulseView 生态、双固件升级、可调逻辑阈值、模拟采样和 3D 外壳整合成完整的可复刻工程。评论区已经形成了较完整的复刻排障知识，但也暴露出几个必须在派生版本中优先处理的风险：旧转接板短路、Type-C/USB 3.0 焊接与识别、QEU6 与 WEU6 的封装和电源域差异、模拟 ADC 量程，以及采样时序验证。

对 WEU6 派生工程而言，原工程可以作为数字采样和软件协议的参考基线；模拟采样、电源控制和下载接口必须按 WEU6 的实际封装重新设计并做独立验证。
